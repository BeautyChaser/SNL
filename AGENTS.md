# Working on SNL

Follow the human's current task and keep work scoped to it. Start by reading the current README, ROADMAP, relevant source files, and Git status.

- This repository begins with design documents and community scaffolding. Do not claim that the CLI or a language standard exists before there is runnable evidence.
- `design-handoff/` is the original, hash-verified reference package. Its execution prompts describe possible future tasks; do not automatically expand a documentation or setup request into the entire MVP.
- Preserve the original handoff and manifest. Put new decisions, proposals, and active implementation outside that historical snapshot, with links back to relevant sources.
- Distinguish established principles, proposed implementations, unresolved questions, and verified behavior. Python, YAML, concrete fields, and CLI spellings remain candidates.
- Humans and AI can propose and refine contracts. Never invent human approval, test results, business correctness, or isolation guarantees.
- Keep SNL text authoritative; generate graphs and IR from it when that tooling exists. Respect public interfaces while retaining freedom over internal implementation.
- For executable changes, run relevant normal and failure checks and report actual commands and outcomes. For documentation changes, verify references, status claims, and examples as appropriate.
- Keep English and Chinese entry points consistent. Chinese and English contributions are both welcome.

The current task takes priority over archived prompts. Licensing and governance are described by the root LICENSE and GOVERNANCE.md.
