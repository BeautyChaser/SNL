# SNL — Codex 实现提示词包

**版本**：2026-11-01 / Prompt Pack v0.1  
**目标**：把此前人—AI 讨论的 SNL（Structured Natural Language）设计转成 Codex 能够逐步落地、验证和继续演化的工程任务。  
**注意**：这是**研发提示词与候选示例包**，不是已经实现的 SNL 解释器/编译器，也不是历史对话的逐字全文。内容依据能够检索到的过往讨论、已确认设计与设计推导整合；未确认的技术细节明确标为候选。

## 如何使用（优先）

1. 将本压缩包**解压**至新的 SNL 仓库根目录（或放在仓库中的 `design-handoff/` 下）。
2. 在仓库根目录启动 Codex，并发送：

   > 请读取 `START_HERE_FOR_CODEX.md`、`AGENTS.md`，按其要求和 `implementation/` 中的验收标准实现 SNL CLI 的第一个可运行闭环。先盘点已有仓库，再建立最小实现和测试；不要仅输出设计文档。完成后运行测试并报告证据。

3. 若需要拆分为多个 Codex 会话，按 `prompts/P0_...` → `P4_...` 依次执行，每次基于前一阶段的实际代码和测试结果推进。
4. 如 Codex 无法读取 ZIP 内文件，先解压；`COMPACT_CONTEXT.md` 是低 token 复述，**不能替代**其他规约与验收标准。

## 文档定位

| 路径 | 用途 |
|---|---|
| `START_HERE_FOR_CODEX.md` | 主执行提示词；要求直接实现可验收 MVP |
| `AGENTS.md` | Codex 持续遵守的人机权限、边界及工程行为 |
| `COMPACT_CONTEXT.md` | 短上下文版本，供新会话快速导入 |
| `docs/` | SNL 语言、活规约、局部作用域、解构、知识治理等产品语义 |
| `implementation/` | 可执行 CLI、IR、里程碑、验收清单 |
| `prompts/` | 各阶段可单独投喂的 Codex 提示词 |
| `examples/` | 提议中的 YAML/报告式规约示例，用于设计与测试，不是既成语言标准 |
| `docs/10_decision_ledger.md` | 区分用户已确认原则、助手提出的建议与待决事项 |

## 成功定义

首轮应交付一个真实的、可安装的命令行工具 `snl`（Windows 可通过 Python 命令调用），能加载多文件 SNL 样例、校验结构与跨文件引用、输出标准化 Contract IR、导出依赖图、生成供 Agent 阅读的上下文包，并用自动化测试证明正常与失败路径。它**不得**假装自然语言已经形式化可判定，不得自动将 AI 的推测“批准”为真实业务契约。

`snl.exe` 是后续 Windows 打包目标，不是第一轮的硬前置条件。SNL 的规范文本是权威来源，图形只是其投影；不应为了 CLI 原型而先建设 GUI、复杂 Agent 平台或电池专用求解器。

## 与真实业务的关系

参数预处理、电池 Workflow 等例子用来证明 SNL 可描述工业软件中的契约、数据流与行为；**SNL 工具本身必须领域无关**，不把 PyBaMM、MOOSE、React Native、某个业务 JSON 绑定成核心语言依赖。

## 把握证据边界

本包力求覆盖可获得的全部关键 SNL 讨论及上下游治理原则，但不能保证逐字覆盖所有历史消息。设计的“确认级别”和“待决问题”可在后续与人继续讨论中修订，且必须留存变更记录。
