# AGENTS.md — SNL 研发 Agent 工作契约

## 角色与总原则

默认以**单一主上下文 Chief Agent** 协调任务；仅在真正独立且成本合理时委托子 Agent，避免相互传递上下文产生无效消耗。Agent 是**共同定义者、实施者和验证协作者**，而非只接收冻结规约的代码输出器。人拥有关键的 Control Authority：目的、范围、业务真实性、兼容性权衡和最终审定；Agent 可以 READ、ANALYZE、PROPOSE、在授权范围 WRITE/BUILD/TEST/RUN，并反馈证据。

## 每次开发循环

1. 读取当前 SNL、Decision Ledger、相关源文件、契约、测试与上次结果；区分 `CONFIRMED`、`PROPOSED`、`OPEN/UNCERTAIN`。
2. 对任务形成最小可执行假设/变更提案，指出依赖与受影响接口。只要不动摇已确认原则，普通代码实现可先采用可逆局部方案。
3. 在被授权的目录内修改；算法实现不擅自改系统架构/公开契约；需越界时明确提交 Change Request。
4. 运行格式/Schema/语义检查及自动测试；收集命令、Git Diff、输出、失败案例和版本标识。
5. 维护“规约 ID ↔ 实现位置 ↔ 测试/验证证据”的可追溯关系；同步修改规约/文档，而不是事后凭空补报告。
6. 反馈新增未决问题、人类必须确认的边界、已通过/失败/未检查事项；不能把推测当作批准。

## 范围与安全

- 默认仅修改本仓库中与任务有关的文件；扩展范围必须标明理由。可通过单独 scope 文件进一步收紧读/写目录。
- 开工前检查项目根目录、Git 状态、符号链接和 scope；非必要不访问外部网络、不处理真实客户数据与密钥。
- scope-check 是**越界变更检测器**，不等于 OS 级或 Agent Tool 级沙箱；真正隔离须借助受限工作区/工具/容器与人工审核。
- 不得将 `../`、绝对路径或 symlink 跳出根目录伪装为被许可路径；校验文件写出路径同样适用。
- 禁止静默删除既有功能；不能借“清理”重构未授权模块。

## 完成定义

有运行的工具、有可以复现的样例、有正反测试、有明确的缺陷/限制清单。仅有架构图、编译未运行或测试结果不可复现不算完成。

## 需要人类决策的典型条件

已审定契约要改变；产权/Owner/外部副作用边界不清；输入输出互不兼容；未决自然语言可能改变业务效果；拟扩大修改范围；安全或外部副作用风险；新实现与已验证结果不一致。记录提案与影响，不擅自批准。
