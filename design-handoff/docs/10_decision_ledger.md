## B. 历次讨论提出、值得实验但未定案的技术选择

| ID | 提议 | 决策级别 | 试验中的默认处理 |
|---|---|---|---|
| P-001 | `.snl.yaml`、YAML 1.2 子集作为载体 | 候选 | 为 MVP 采用，保持解析/语义分离 |
| P-002 | JSON Schema + Semantic Validator + Tests 三段检查 | 候选 | 做最小闭环 |
| P-003 | 根类型 `Project/Entity/Capability/Component/Workflow` 与相关字段名 | 候选 | 先保持最小兼容性并版本化 |
| P-004 | `OPEN/DRAFT/APPROVED/SUPERSEDED` 状态、局部审定内容哈希 | 部分方向已确认，枚举/数据结构候选 | 首版支持基础 gating，局部精细审定后续加强 |
| P-005 | `snl init/validate/build/graph/pack/verify/diff/scope-check` 子命令及参数名 | 功能目标基本确认；命令细节候选 | 按实现/验收文档实现可逆命令界面 |
| P-006 | 用 DOT/Mermaid 作为图投影 | 候选 | 先用无需 GUI 的一种 |
| P-007 | Python CLI（PyYAML、jsonschema、pytest；PyInstaller 出 .exe） | 候选 | 新仓库优先，Windows/Linux 可运行 |
| P-008 | 按 role/target/token budget 打包 Agent Bundle | 能力方向确认；预算算法候选 | MVP 提供可追踪预算估计 |
| P-009 | 步骤 ID、`action/decision/merge/loop/error`、检查级别 | 候选 | 逐步实践，保持自然语言原文 |
| P-010 | 通过 Git diff/allowlist/symlink 检测 scope | 候选实现 | 只声称“检查”，不声称沙箱 |

## C. 尚未作出的产品决策

语言语法的正式标准、语义版本策略、审批身份与审计机制、跨仓包管理与依赖锁、类型系统/单位系统程度、表达式求值的信任边界、上下文 budget 计量、图类型与 GUI 形态、迁移与部署模式、开源许可证、Scope 的 OS 级安全绑定，都仍属可实验/待定议题。具体见 `11_open_questions.md`。
