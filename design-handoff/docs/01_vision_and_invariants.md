# 01 — SNL 的定位、目标与不可破坏原则

## 正式定位

**SNL — Structured Natural Language**：面向大语言模型的契约式编程语言。更深层的定位是：**一套让软件定义能够在人类与 AI 长期协作中持续演进的工程基础设施**。

SNL 同时是：

- 人与 Agent 共同维护的结构化自然语言工作界面；
- 可解析、可校验、可引用、可局部审定的接口/行为/组合约束源；
- 用于选择上下文、控制实施作用域、提出候选实现、检查证据和回写修订的“收束”媒介；
- 后续能由 CLI 导出机器 IR、架构/组合/数据流/流程图的文本权威源。

它**不是**：保证最初需求就正确的冻结需求工具；自然语言“零歧义编译器”；代替数值求解器的 DSL；仅让 Agent 按 Prompt 行事的模板集；OpenSpec 的目录克隆；只能用特定商业 LLM 的系统；必须使用 GUI 才能工作的平台。

## 必须始终成立的不变量

**I-01 契约优先，内部实现自由。** 约束公开输入/输出、行为、前后置条件、公开能力、错误/异常、副作用、不变量、所有权和验收，而不规定必须有哪些私有类/方法、具体算法、Python 或 C++。模块代码可以黑箱，但对外契约必须白箱。

**I-02 人—AI 双向协作。** Agent 不仅编码，还参与规约增/删/改/查、挑战假设、提出实验、整理证据。人并不需要亲自写完复杂规约；人保留意图、影响重大的契约和风险的控制与审定权。

**I-03 活规约而非伪稳定。** 初始想法可能模糊、错误、彼此冲突；必须允许讨论、提案、验证后修订、局部审定以及推翻。已审定的部分在新审批前保持当前生效基线；非审定的不得冒充正式定义。

**I-04 文本权威，图仅投影。** 多文件 SNL → Contract IR → graph/UI。不能要求 GUI 用户手工维护一份与 SNL 不一致的平行权威流程定义。图应按稳定 ID 追溯到源文件。

**I-05 逐层收束不确定性。** 自然语言探索产生多个候选，契约、Scope、前后置条件、Schema、测试、可复现证据逐步收窄；不能凭 LLM 的自信评价将某个候选等同已证实正确。

**I-06 局部作用域受控。** 每一轮开发具有目标文件夹、可修改边界、接口、验收/停止条件。Scope 是随阶段变化的治理协议，而非所有项目都只有一个永久锁死的目录。

**I-07 可部分解构。** 原先封闭模块可以只拆出一部分可复用能力，未拆部分保留原状；整条 Workflow 继续可运行。拆到可治理实现单元即可，无须每行代码显式声明。

**I-08 证据链优先。** SNL ID ↔ 编码位置 ↔ 自动/人工验证 ↔ Git 修订/审定记录；明确“已验证/未验证/无法机器判断”。

**I-09 实现与场景解耦。** SNL CLI 是领域无关、模型/GUI 无关的开源工具；电池仿真只是适配验证样例。

## 认知/沟通类比

SNL 类似“由人和 AI 协同编写，面向 AI 的多文件结构化演讲稿”：需要考虑目标 Agent 的角色、任务、上下文预算、认知入口和可执行表达顺序。它组织的不只是输出指令，还包括假设、分歧、证据、未决问题、适用范围及变更理由。因此它在架构上不仅是 Syntax+Schema，也是一套长期协作的外部认知结构。

## 可用性边界

第一阶段只能证明：结构解析、形式化字段校验、可确定的静态引用检查、可追踪的上下文装配与可运行测试。对“实现与自然语言完全等价”不能作一般性承诺；必须借助明确测试、形式化断言、审查或特定领域模型额外证明。
